# v1.3.0 release plan

This note is a plan. It does not publish a release, move a tag, or change the `v1` major tag.

## What the tags point at today

Verified from the local repository on 2026-11-08:

| Ref | Commit | Date |
| --- | --- | --- |
| `v1` | `8194e51ab288818b14584f46cd4a5b5d95bf7c76` | 2026-04-09 |
| `v1.2.1` | `8194e51ab288818b14584f46cd4a5b5d95bf7c76` | 2026-04-09 |

`v1` and `v1.2.1` are the same commit. `main` has moved past that commit. The commits after `v1.2.1` include the security-context and evidence-backed change review work, later dependency bumps, and the configurable Claude 5.5 model input. None of that is on the published `v1` tag.

`uses: cybrking/thr8@v1` therefore still runs the April 2026 action. That build hardcodes `claude-sonnet-4-6` and does not accept the `model` input.

## Proposed release

Tag the commit that contains this model change, plus the unreleased `main` work it sits on, as `v1.3.0`. Do that in a separate maintainer step after review.

Moving `v1` from `8194e51` to that release is also a separate decision. It changes every workflow that pins the floating major. Leave `v1` where it is until that decision is explicit.

Suggested release notes for that future tag:

- Add the `model` input. The default is `claude-sonnet-5-5`. The only override is `claude-opus-5-5`. Other IDs fail the job and are not replaced.
- Discovery, threat generation, continuations, and optional remediation use the selected model. Reports record it.
- Sonnet 5.5 requests send `thinking: { type: "between_tools" }` and `output_config.effort: "high"`, through `@anthropic-ai/sdk` 1.6.0 (`anthropic-version: 2026-10-21`). Opus 5.5 requests send adaptive thinking at effort `medium` and stream because their output budget exceeds the SDK non-streaming limit. The stream client timeout is 30 minutes so the 64000 cap is not aborted at the SDK's 10 minute default. `claude-sonnet-4-6` is not an accepted input.
- Refusals, truncated output, and malformed JSON fail the assessment or skip the fix. They are not repaired into a clean result.
- The Claude Code plugin is unchanged and keeps using the Claude Code session model.

No live comparison against `claude-sonnet-4-6` was run for this change. The offline harness in `eval/model-comparison.js` records the request differences and fixture facts only.
